Point2Vec vs Point2VecPCP

A side-by-side HTML diagram of how the original Point2Vec pretraining path differs from the PCP-style variant. The key change is that Point2VecPCP predicts the masked positional embedding first, then feeds the predicted position into the decoder instead of using the ground-truth masked position directly.

Original Point2Vec

Decoder receives the ground-truth masked positional embedding. This makes reconstruction easier, but it also means the encoder is not forced to infer masked geometry as strongly.

Baseline

1. Tokenize Point Cloud

points: (B, N, 3)

tokenizer(points) produces patch tokens and patch centers: embeddings: (B, T, C), centers: (B, T, 3). Then masking(centers) selects visible and masked patches.

2. Student Sees Only Visible Patches

visible_embeddings, visible_pos

Visible tokens are concatenated with a class token and encoded by the student transformer. The student returns visible patch features and a global class feature student_cls.

3. Decoder Uses Ground-Truth Masked Position

decoder pos = [visible_pos ; masked_pos]

The masked branch is reconstructed with decoder inputs formed from visible encoded tokens, masked placeholder tokens, and the real masked positional embedding from positional_encoding(centers).

4. Teacher Builds Token Targets

targets_full: (B, T, C)

The EMA teacher sees the full token sequence and produces regression targets. The masked subset becomes the target for ssl_loss.

5. Losses

Total loss:
ssl_loss + cls_ce_lambda * cls_ce_loss

There is no explicit objective forcing the model to predict masked geometry before decoding.

Point2VecPCP

A PCP-style positional prediction branch is inserted before the decoder. The decoder now consumes predicted masked position instead of the ground-truth masked position.

PCP Variant

1. Tokenize Point Cloud

points: (B, N, 3)

Same start as the baseline: tokenizer(points) gives embeddings and centers, then masking(centers) splits patches into visible and masked sets.

2. Student Encodes Visible Patches

output_embeddings, student_cls

The visible branch stays the same as the original Point2Vec path. This keeps the main encoder design unchanged while adding a new auxiliary geometric task.

3. New PCP Branch Predicts Masked Position

[visible_pos ; mask_pos_token] -> pos_decoder -> pred_pos_proj

A dedicated positional branch uses a learnable mask_pos_token instead of the true masked position. The branch outputs predicted_masked_pos, which is trained to match the real masked positional embedding.

4. Decoder Uses Predicted Masked Position

decoder pos = [visible_pos ; predicted_masked_pos.detach()]

The decoder now reconstructs masked token targets using inferred position rather than the ground-truth masked position. By default, the predicted position is detached before decoder input for training stability.

5. Teacher Still Provides Token Targets

targets_full: (B, T, C)

The EMA teacher path remains unchanged. This preserves the original masked token regression objective while adding a new geometric bottleneck before reconstruction.

6. Losses

Total loss:
ssl_loss + cls_ce_lambda * cls_ce_loss + pcp_pos_prediction_lambda * pos_loss

New term: pos_loss = distance(predicted_masked_pos, masked_pos)
